# PLC 비동기·동기 통신 실습 spec

원문은 `C:\Users\135\Documents\카카오톡 받은 파일\TASKS.md`다. 이 문서는 과제가 "spec에 정한다"고 맡긴 동작을 정한다.

## 1. 사실과 확인 상태

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 통신 | RS485, Modbus RTU, 9600, 국번 1 | TASKS.md |
| 대상 | D01000 한 워드. 읽기 FC03 주소 0 수량 1, 쓰기 FC06 주소 0 | TASKS.md |
| COM 포트 | COM5 (Silicon Labs CP210x) | 사용자 확인 |
| 형식 | 데이터 8, 패리티 없음, 정지 1 (8N1) | 실제 PLC 응답으로 확인. XG5000 설정값 대조는 미확인 |
| 환경 | Python 3.13.11, PyModbus 3.16.2, pyserial 3.5 | 이 PC(C:\Users\128)에서 확인, 자동 테스트 60개 통과 |

강사 확인 사항(D01000 미사용, 실습선에 국번 2 없음)은 실제 시험 전에 사용자가 확인한다.

**통신 형식 정정:** 처음에는 8E1로 작성했으나 실제 PLC가 응답하지 않았다. 같은 FC03 읽기를 형식별로 보낸 결과 8E1·8O1은 무응답, 8N1·8N2는 CRC가 맞는 응답(`01 03 02 12 34 B5 33`)이었다. 8N2의 응답은 정지 비트를 구별하는 근거가 되지 못하므로, 표준 구성인 8N1을 쓰고 XG5000 대조를 남긴다.

PyModbus 3.16.1 소스에서 확인한 동작:
- 호출 형식은 `read_holding_registers(0, count=1, device_id=n)`, `write_register(0, value, device_id=n)`다.
- 무응답이면 동기·비동기 모두 `retries` 소진 뒤 `ModbusIOException`을 던진다.
- PLC가 Modbus 예외로 응답하면 예외 없이 `isError()`가 참인 응답이 돌아온다.
- 비동기 클라이언트는 Windows에서 이벤트 루프 안의 폴링 태스크로 직렬 포트를 읽는다.

## 2. 파일

```text
plc_config.json      통신·주기 설정. 두 프로그램이 같은 파일을 읽어 조건을 맞춘다
plc_common.py        설정, 명령 해석, 상태, 기록, 키 입력, 스케줄 판단
plc_project.py       과제 1. asyncio 비동기판
plc_project_sync.py  과제 2. 단일 실행 흐름 동기판
tests/               자동 테스트
logs/                실행별 JSONL 기록
docs/                spec, plan, 실행 방법, 시험 기록, 비교 기록
```

설정 기본값: `port=COM5, baudrate=9600, bytesize=8, parity=N, stopbits=1, station=1, timeout=2.0, retries=0, poll_interval=1.0`

timeout 2초와 retries 0은 과제가 허용한 시험용 값이고, 정상·무응답·복원 시험과 두 프로그램에 모두 같은 값을 쓴다.

명령행 옵션은 `--station {1,2}`와 `--config <경로>` 둘이다. `--station`은 설정 파일의 국번보다 우선한다.

## 3. 입력

두 프로그램의 입력 방식은 같다. 터미널에서 한 줄을 입력하고 Enter를 누른다.

| 명령 | 동작 |
| --- | --- |
| `write <값>` | D01000 쓰기 요청. 값은 0~65535 정수 |
| `station <1 또는 2>` | 요청 대상 국번 변경 요청 |
| `status` | 현재 상태를 바로 표시. 통신하지 않음 |
| `quit` | 종료 |

- 키는 `msvcrt`로 비차단 확인한다. 스레드나 차단형 `input()`을 쓰지 않으므로 동기판도 감시와 입력을 번갈아 처리할 수 있다.
- 입력 글자는 프로그램이 처리할 때 직접 화면에 찍는다. 글자가 보이는 시점이 곧 프로그램이 키를 읽은 시점이다.
- Ctrl+C는 종료로 처리하고 기록에 `reason=ctrl_c`를 남긴다. 키 입력이 아니라 운영체제 신호라서 입력 지연과 별개다. 시험 서버(`socket://`)에서는 동기판도 대기 중 바로 끊겼으며, 실제 COM 포트에서 같은지는 시험으로 확인한다.
- 잘못된 명령과 범위 밖 값은 통신하지 않고 `request_rejected`로 기록한다. 국번 0과 3 이상은 항상 거절한다.

## 4. 처리 원칙 (두 판 공통 출발점)

- **연결당 한 요청:** 통신은 한 번에 하나만 진행한다.
- **연속 요청:** `write`와 `station`은 접수 순서대로 대기열(FIFO)에 넣는다. 대기열 크기는 제한하지 않으며, 새 요청이 이전 요청을 대체하지 않는다.
- **순서 보존:** `station`도 대기열 순서로 적용한다. `write 100`, `station 2` 순서면 100은 이전 국번으로 보낸다.
- **통신 차례:** 한 회차에 대기열 요청 하나를 처리하고, 그다음 감시 주기가 되었거나 직전 쓰기가 성공했으면 읽기를 한 번 한다. 그래서 요청이 밀려도 감시가 멈추지 않는다.
- **감시 주기:** 읽기 시작 시각 기준 1초다. 대기로 늦어지면 밀린 횟수를 몰아서 읽지 않고 한 번만 읽는다.
- **재시도 없음:** 실패한 쓰기를 다시 보내지 않고, 대기 중 요청을 복원 시 일괄 재전송하지도 않는다. 대기열에 남은 요청은 차례가 되면 그 시점의 국번으로 한 번 시도한다.
- **쓰기 확인:** 쓰기 응답 성공은 `write_result`일 뿐이다. 값 확인은 이후 읽기의 `observation`에 `expected`와 `matches`를 붙여 판단한다.

## 5. 상태와 표시

표시 상태는 셋을 구분한다. 읽기 실패 시 관측값을 지우거나 0으로 바꾸지 않는다.

- **마지막 정상 관측:** 값, 관측 시각, 읽은 국번. 성공한 읽기가 없으면 `미관측`.
- **최근 읽기 결과:** 마지막으로 끝난 읽기의 정상·실패(사유).
- **응답 대기:** 통신 중이면 경과 시간을 따로 표시한다. 대기 표시가 직전 실패를 가리지 않게 하려고 최근 결과와 분리했다.
- **요청 대상 국번과 대기열 길이.**

표시 주기(0.5초)마다 `heartbeat`를 기록한다. 통신 대기 중이면 경과 시간 안내도 화면에 찍는다. 같은 코드가 두 판에 있으므로 `heartbeat` 간격이 곧 로컬 표시가 멈춘 시간의 측정값이 된다.

**비동기판:** 입력·표시·통신을 코루틴으로 분리한다. 무응답 대기 중에도 명령을 접수하고, `status`에 바로 응답하며, 안내를 갱신한다. `quit`은 대기를 취소하고 바로 종료한다.

**동기판:** 한 루프에서 입력 확인 → 표시 → 통신을 차례로 한다. 통신 함수가 반환될 때까지 입력·표시가 지연되고, `quit`도 반환 후 처리한다. 이 지연은 수정 대상이 아니라 기록 대상이다.

## 6. 기록

실행마다 `logs/plc-<async|sync>-<시각>.jsonl`을 만들고, 터미널 첫 줄에 경로를 알린다. 모든 줄에 `type`, 시작 후 경과 초 `elapsed`, 현지 시각 `time`이 들어간다.

| type | 의미 |
| --- | --- |
| `started` | 판 종류와 전체 설정 |
| `key_seen` | 프로그램이 키를 읽은 시점 |
| `request_accepted` | 명령 접수. 대기열 길이 포함 |
| `request_rejected` | 명령 거절. 사유 포함 |
| `status_shown` | `status` 응답 |
| `comm_start` / `comm_end` | 통신 호출 시작·반환. 종류, 국번, 소요 시간 포함 |
| `write_result` | 쓰기 결과. 값, 성공 여부, 실패 사유 |
| `station_changed` | 국번 변경 적용 |
| `observation` | 성공한 읽기. 값, 국번, 관측 시각, `expected`, `matches` |
| `read_failed` | 실패한 읽기. 사유. 값 필드 없음 |
| `heartbeat` | 표시 주기 동작 |
| `stopped` | 종료 |

**입력 시도 시점의 한계:** 동기판은 통신 중 키를 읽지 못해 키를 누른 정확한 시각을 프로그램이 알 수 없다. 시험에서는 `comm_start`가 찍힌 직후에 입력하고, 눌렀을 때 글자가 안 보이는 것과 `key_seen` 시각을 근거로 삼는다. 범위는 `comm_start`~`key_seen`으로 적는다.

## 7. 오류 처리

- 시작할 때 포트를 열 수 없으면 원인을 표시하고 종료 코드 1로 끝난다.
- 실행 중 통신 예외(`ModbusException`, `OSError`), Modbus 예외 응답, 값 개수가 1이 아닌 응답, 기능 코드가 요청과 다른 응답은 해당 요청의 실패로 기록하고 감시를 계속한다. 늦게 도착한 다른 요청의 응답을 관측값으로 쓰지 않기 위해서다.
- 비동기판은 라이브러리의 폴링 태스크가 죽으면 포트를 다시 열고 `port_reopened`로 기록한다.
- 종료 시 어떤 경로든 포트를 닫는다.

## 8. 검증

**자동(Claude 수행, PLC 없이):**
- 명령 해석, 범위 검증, 통신 차례 판단의 단위 테스트
- `socket://` URL로 로컬 RTU 시험 서버에 연결해 실제 PyModbus 스택을 거치는 통합 테스트. 국번 1만 있는 서버로 쓰기→재조회, 국번 2 무응답, 그동안의 입력 처리를 확인한다. `socket://` 방식이 비동기판에서 동작하지 않으면 계획 단계에서 대안을 정해 기록한다.
- 동기판 소스에 `asyncio`, `threading`, `multiprocessing` 등이 없는지 검사

**실제 PLC(사용자 수행):** 과제의 세 시험을 두 판에서 각각 수행한다. 순서와 명령은 실행 안내 문서에 적고, 나온 로그를 함께 검토해 시험 기록표와 비교 기록을 작성한다. 실제 PLC로 실행하기 전까지 해당 항목은 "미확인"으로 둔다.

## 9. 범위 밖

- 선택 실습(요청이 몰릴 때 처리 원칙 변경)은 두 구현과 비교를 마친 뒤 별도로 결정한다.
- 대기열 저장·복원은 하지 않는다. 재시작하면 대기열은 사라지고, 시작 시 관측은 `미관측`이다.
- D01000 외 영역은 어떤 명령으로도 접근하지 않는다. 주소는 코드에 0으로 고정한다.
