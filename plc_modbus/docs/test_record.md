# 시험 기록

## 실제 PLC (과제 제출용)

세 시험은 아직 실행하지 않았다. `docs/run_guide.md` 순서로 실행한 뒤 실제 결과와 로그 파일명으로 채운다.

**지금까지 확인한 것:** 8N1 설정으로 동기·비동기 클라이언트가 국번 1의 D01000을 각각 3회 읽어 모두 4660을 받았다(응답 약 0.03초). 쓰기는 아직 보내지 않았다. `logs/`의 2026-11-05 17:33~17:39 실행 로그 12개는 8E1 설정 때의 것으로, 성공한 읽기가 한 건도 없고 실패 기록은 값 없이 남아 있다.

| 시험 | 비동기판의 실제 결과·증거 | 동기판의 실제 결과·증거 |
| --- | --- | --- |
| 정상 감시 중 값 변경 | 미확인 | 미확인 |
| 국번 2로 읽기 요청 중 입력·표시 | 미확인 | 미확인 |
| 국번 1로 복원 | 미확인 | 미확인 |
| 국번 2 시작 시 미관측 | 미확인 | 미확인 |

**PLC 시험에서 적을 것:** 사용한 timeout·retries, 복원을 실행 중 변경으로 했는지 재시작으로 했는지, 시작 값, XG5000 관측 값.

## 시험 서버 결과 (PLC 아님)

`tests/rtu_server.py`는 국번 1만 응답하고 국번 2에는 아무것도 보내지 않는다. 두 프로그램은 `plc_config.json`과 같은 timeout 2초, retries 0, 감시 1초로 실행했고, 포트만 `socket://`으로 바꿨다. 키는 `tools/console_drive.py`가 콘솔에 넣은 실제 키 이벤트다. 로그는 `logs/local_server/`에 있다.

| 시험 | 비동기판 (`plc-async-20261105-174542-410435`) | 동기판 (`plc-sync-20261105-174552-773755`) |
| --- | --- | --- |
| 정상 감시 중 값 변경 | 100, 200 모두 쓰기 성공 후 재조회 `matches=True` | 같음 |
| 국번 2로 읽기 요청 중 입력·표시 | 키 읽기 0.030~0.045초. 대기 중 `status` 응답, 표시 최대 간격 0.523초 | 키 읽기 1.970~1.989초. 대기 중 키 0건·표시 0건, 표시 최대 간격 2.222초 |
| 국번 1로 복원 | 새 관측 갱신, `write 400` 재조회 일치 | 같음 |

자동 테스트 60개 통과. 국번 2 시작 시 `미관측`, 서버 연결 끊김 뒤 관측 재개, 잘못된 입력 무시도 자동 테스트로 두 판 모두 확인했다.

## 미확인 항목

- XG5000의 실제 통신 형식이 8N1인지 (응답으로만 확인했고 8N2와 구별되지 않음)
- 실제 PLC로의 쓰기와 세 시험 전체
- 실제 USB 어댑터를 뽑았다 꽂을 때의 복구. 비동기판 복구 코드는 폴링 태스크를 강제로 죽인 시험으로만 확인했다
- 실제 COM 포트의 동기판에서 대기 중 Ctrl+C가 바로 끊기는지
- 사람이 직접 입력할 때의 화면 표시 (자동 시험의 화면은 숨겨진 콘솔이었다)
